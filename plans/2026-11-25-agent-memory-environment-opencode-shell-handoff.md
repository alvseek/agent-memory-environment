## Objective

Keep the Windows system awake when an OpenCode background shell finishes and its parent session still has the result to process. Let the system sleep normally when that work is done.

## Specification

- The incident gives a failing timeline: the Einherjar shell completed at 10:57:49 local time, Joro released its request that second, and Windows recorded 443 seconds of sleep before the parent reported a credential-refresh timeout at 11:05:13. The renewal of credentials is work to protect; a network failure while continuously awake is a separate issue.
- For a result that will resume a parent, transfer protection without a release/reacquire gap, including before model dispatch. Bind the transfer to the correct shell and parent. Normal shells with no continuation must still release. Preserve independent shell protection, existing human-input wait behavior, and cleanup on success, error, interruption, and plugin disposal.
- Change Joro's OpenCode adapter and its focused tests. Do not change Einherjar, OpenCode authentication, Windows power settings, the user's active installation, or the separate Store branch. Installation, publication and a version bump are not part of this plan.
